# 同桌 · TABLEMATES

给面对面的朋友使用的德州扑克网页。每位玩家用自己的手机打开网页，通过房间码或邀请链接入座。

也支持单机模式：开局选择“单机模式”，设置总人数（你和 1–7 个机器人）、初始筹码、轮数和盲注，即可直接对局。单机模式不连接 PeerJS，也不需要其他玩家在线。

机器人基于自己的手牌、公共牌和随机模拟估算胜率，结合跟注成本执行弃牌、过牌、跟注或加注，不读取其他玩家的底牌。每轮结算后由玩家开始下一轮；刷新页面可恢复正在进行的单机对局。

## 本地运行

需要 Node.js 22。

```sh
npm install
npm run dev
```

```sh
npm test
npm run build
```

## 对局

- 准备页独立提供单机、创建房间和加入房间；联机玩家在等候区入座，房主开始后统一进入牌桌。刷新恢复也会回到对应牌桌。
- 牌桌独立全宽展示；跟注为金色、过牌为青色、加注为蓝色、全下为红色，配合行动提示。加注支持金额输入、滑块和底池预设。
- 2–8 人；房主设置每人初始筹码、轮数、小盲注，大盲注为两倍小盲。
- 房主创建房间，分享房间码或邀请链接。至少两位玩家在线即可开始。
- 自动洗牌、发底牌、收盲注和轮换庄家。支持弃牌、过牌、跟注、加注、全下。
- 每条街下注完成后自动发公共牌；全下后自动跑完牌面。
- 使用 pokersolver 比牌，支持平分底池、边池和未跟注筹码退回。
- 达到轮数，或仅一人仍有筹码时结束。本局结果只在当前页面展示，结束时清除本机缓存。
- 进行中的房间只保存恢复所需的当前状态，不记录历史牌局。页面刷新后点击“恢复上次对局”。房主恢复后，其他玩家也需要重连。

## 连接与隐私

纯静态前端，没有自建服务器和数据库。PeerJS 的公共信令服务负责找到其他玩家，牌局使用 WebRTC 数据通道同步。它不是仅靠 localStorage 联机：首次连接需要互联网和外部信令服务。

房主负责权威牌局状态、洗牌和结算；只向每位玩家发送其自己的底牌，摊牌时公开仍在争夺底池的手牌，牌堆始终不发送给其他玩家。对局中的底牌默认遮盖，可自行展开。

房主浏览器持有完整牌局，适用于互相信任的朋友娱乐，不提供防房主作弊的保证。房主需保持网页开启，手机锁屏和浏览器后台休眠可能导致连接中断。没有断线自动弃牌，断线玩家恢复后继续行动，或由房主结束整场牌局。

公共信令服务没有可用性保证，某些 Wi-Fi、运营商或受限网络无法建立直连。默认使用 PeerJS 提供的公共 STUN/TURN 配置，没有配置专属中继；跨网络连通性无法保证。可将 `.env.example` 复制为 `.env.local`，通过 `VITE_ICE_SERVERS` 配置自己的 TURN 服务，再重新构建。Vite 环境变量会进入前端产物，应使用服务商允许公开在前端的受限凭据。GitHub Actions 构建时可通过仓库变量 `VITE_ICE_SERVERS` 配置。

## 部署到 GitHub Pages

1. 在 GitHub 创建仓库，并将本目录推送到 `main` 分支。
2. 进入仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
3. 仓库 **Actions** 中的 **Deploy to GitHub Pages** 工作流会自动测试、构建和部署，也可以手动运行。
4. 使用部署产生的 HTTPS 地址创建房间和邀请朋友。

已经配置相对资源路径和 Hash 路由，支持 `https://用户名.github.io/仓库名/`，无须填写仓库名。若主分支不是 `main`，需要修改 `.github/workflows/deploy.yml` 的触发分支。

不需要 API key、数据库或服务器密钥。localStorage 只保存在各自浏览器，不会上传到 GitHub。结束房间会通知在线玩家清除本局缓存；已离线设备需要在重连失败后主动离开房间清除本机缓存。

## 当前验证范围

已通过 TypeScript 检查、生产构建及 21 项测试（含 100 场不同人数的模拟对局、机器人合法行动与信息隔离、单机恢复、定时器清理和行动提示金额）。单机浏览器测试验证了机器人自动行动、完整对局、刷新恢复、筹码守恒、结束清理，以及没有外部连接。联机浏览器测试在模拟传输下验证了独立玩家的底牌隔离、完整两轮下注与结算、房主刷新恢复、玩家重连、缓存清除和结束房间。已检查准备页与牌桌跳转、操作按钮、桌面、手机及八人牌桌布局。

当前开发网络中公共信令能连接，但真实 WebRTC 数据通道连接超时，因此真实手机联机尚未验证成功。正式使用前需在目标网络上复测；连接失败时需要可用的 TURN 服务。这一限制不等同于模拟传输测试通过。
